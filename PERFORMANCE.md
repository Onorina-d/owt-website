## Что было причиной и что изменено

1. Слайд-шоу hero стартовало сразу: экран менялся непрерывно (Speed Index 34,7 с), слайды 2–3 качались при загрузке.
   → Слайд-шоу запускается при первом действии посетителя (или через 12 с), слайд скачивается только перед показом.
2. На телефоне качался горизонтальный кадр hero и растягивался на вертикальный экран.
   → Отдельный вертикальный кадр 3:5 (та же фотография, та же обработка) с собственной предзагрузкой — резче и легче.
3. Нативная ленивая загрузка на медленной сети начинала качать фото за ~2500 px: на странице проекта сразу грузились все 11 фото.
   → Собственная ленивая загрузка «за один экран до появления» (с <noscript>-копией).
4. Правило `html:has(...)` для липкого подменю заставляло пересчитывать стили всего документа при каждом изменении.
   → Заменено классом на `<html>`, состояние шапки пишется только при изменении.
5. Первая раскладка всей длинной страницы выполнялась синхронно внутри стартового скрипта.
   → Первый расчёт геометрии после первой отрисовки; некритичные модули — в `requestIdleCallback`;
     секции ниже первого экрана — `content-visibility: auto`; прокрутка не читает геометрию далёких секций (IntersectionObserver).
6. Три CSS-файла блокировали первую отрисовку → весь CSS встроен в HTML (~12 КБ gz).
7. Шторки изображений анимировали CSS-переменную → прямая анимация `clip-path`.
8. Блокировка прокрутки `body {overflow:hidden}` и «шторка» меню через clip-path вызывали перерисовку всей страницы при открытии/закрытии меню.
   → Без блокировки (`overscroll-behavior: contain`), шторка — двумя встречными transform на видеокарте.
9. Первые экраны внутренних страниц ждали скрипт для появления → CSS-анимация с первой отрисовки.
10. SVG-логотип повторялся в каждом HTML три раза → символ + `<use>`, логотип подвала — кэшируемый файл.

Сторонних ресурсов, видео и анимационных библиотек при загрузке нет (YouTube грузится только при открытии видео).
Изображения других страниц на главной не загружаются.
